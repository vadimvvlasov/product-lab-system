# Handoff: Coding Agent Workflow Kit — commercial experiment in Product Lab System

**Purpose:** передать главному/ведущему coding agent задачу, чтобы он запустил штатный процесс Product Lab System с оркестрацией ролей, а не просто внёс изменения по одному длинному промпту.

## Что внутри

- `00-ORCHESTRATOR-PROMPT.md` — готовая стартовая инструкция, которую нужно вставить в coding agent, открытый в корне репозитория `product-lab-system`.
- `01-OWNER-BRIEF.md` — цель, гипотеза, границы полномочий и рабочие предположения владельца.
- `02-SYSTEM-GAP-AUDIT.md` — обязательная проверка, что реально отсутствует в текущей методологии, и ограничение на изменение системы.
- `03-COMMERCIAL-EXPERIMENT.md` — проектная постановка первого коммерческого теста.
- `04-WORKFLOW-KIT-MVP.md` — минимальный состав цифрового продукта, который потенциально можно продавать.
- `05-ACCEPTANCE-QA.md` — критерии завершения и независимой QA-проверки.

## Как использовать

1. Распаковать этот архив в любое удобное место. Не копировать всё автоматически в канонические папки репозитория.
2. Открыть coding agent **в корне** локального клона `product-lab-system`.
3. Вставить содержимое `00-ORCHESTRATOR-PROMPT.md` как задачу для ведущего агента. Промпт ссылается на остальные документы этого пакета по именам. Если агент не видит соседние файлы, скопировать папку в `_docs/handoffs/coding-agent-workflow-kit/` либо передать файлы как вложения.
4. Агент должен сначала проверить рабочее дерево, доступность subagents, GitHub/CLI и текущие эксперименты. Он не должен предполагать, что все инструменты доступны.
5. Пусть агент создаёт проектные записи через существующие шаблоны и методологию, запускает PM/spec → implementation → independent QA, и сохраняет отчёт.
6. **Не разрешать публикацию поста, отправку сообщений, настройку/взимание оплаты, push, merge или deploy автоматически.** Агент готовит материалы и локальные изменения; внешние действия остаются за владельцем.

## Принципиальное решение

Это не запрос на немедленную реализацию большого «Content-to-Revenue feature». Репозиторий уже содержит связанные поля и правила в `templates/idea.md`, `templates/experiment-s.md`, `templates/experiment.md`, `system/30-experiment.md` и `system/00-model.md`. Поэтому сначала нужно проверить, чего именно не хватает в использовании этих механизмов. Предпочтительная минимальная системная доработка — сквозной пример коммерческого content-led эксперимента, если такой пример действительно отсутствует или неполон.

Коммерческая проверка Coding Agent Workflow Kit — отдельная ветка работы. Не смешивать доказательство технического качества workflow с доказательством платежеспособного спроса.
