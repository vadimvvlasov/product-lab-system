# 05. Analytics & Monitoring

## Цель

Наблюдать полный путь от источника привлечения до полезного результата и повторного использования, при этом не собирать чувствительные данные без необходимости.

## Минимальные группы событий

Имена событий могут отличаться между продуктами; важно сохранять единый смысл.

| Группа | Примеры событий |
|---|---|
| Acquisition | `landing_view`, `source_landed`, `campaign_clicked` |
| Activation | `signup_completed`, `first_core_action_started`, `first_value_completed` |
| Core usage | `feature_started`, `feature_completed`, `result_opened`, `result_exported` |
| Quality | `result_rated`, `error_reported`, `task_failed`, `correction_submitted` |
| Retention | `second_core_action_completed`, `return_session`, `feature_reused` |
| Monetization | `pricing_viewed`, `checkout_started`, `payment_completed`, `subscription_cancelled` |
| Operations | `api_error`, `provider_error`, `timeout`, `queue_lag`, `latency_recorded` |

## Обязательные свойства события

Где уместно, записывай:

- `event_name`;
- timestamp;
- anonymous/user ID с минимально необходимой точностью;
- `project_id`, `experiment_id`, `variant`;
- `source`, `medium`, `campaign` или сохранённый first-touch attribution;
- версию приложения/модели/промпта;
- status, duration, error category;
- агрегированные свойства, необходимые для сегментации.

Не включай сырой текст, пароль, токен, полный запрос, содержимое договора, персональные данные или секреты в обычную аналитику. Для диагностики AI используй минимальные безопасные метаданные и контролируемые доступы к отдельным журналам.

## Воронка

Общая схема:

`qualified_visit → signup → core_action_started → core_action_completed → value_used → return → paid`

Для каждого продукта определить собственные `core_action` и `value_used`. Сегментировать по источнику, когорте, выбранной функции и числу прошлых использований. Если у функции узкий сегмент, считать conversion только среди пользователей, которые потенциально могли ею воспользоваться.

## Метрики продукта и качества — разные

**Продуктовые:** активация, завершение основного сценария, повторное использование, переход к оплате, отмена, время до получения ценности.

**Технические:** error rate, latency p50/p95, timeouts, доступность зависимости, стоимость на выполненную операцию, размер очереди.

**Качество результата:** полезность, частота исправлений/отказов, верификация результата, false positives/false negatives для классификатора, успешность запросов агента.

Успешный HTTP-ответ сам по себе не означает, что результат полезен пользователю.

## Мониторинг до релиза

Перед включением функции проверить:

- события видны в dashboard/logs;
- параметры эксперимента и источника сохраняются;
- error и latency можно отличить от отказа пользователя;
- чувствительные данные не попадают в события;
- alert/порог существует для критичных технических отказов;
- rollback или feature flag работает;
- определено, кто и когда проверит результаты.

## Минимальный dashboard

1. посещения и источники привлечения;
2. конверсии по шагам воронки;
3. число уникальных целевых пользователей и абсолютные counts;
4. завершение основного сценария по версии/эксперименту;
5. повторное использование в релевантном сегменте;
6. paid conversion и выручка, если применимо;
7. ошибки и latency;
8. качество результата и пользовательские коррекции;
9. стоимость на завершённый полезный сценарий.

## Интерпретация

- **Мало переходов:** возможно, проблема с каналом, охватом или предложением.
- **Есть переходы, нет активации:** проверить аудиторию, доверие, onboarding и требования к первому действию.
- **Есть активация, нет полезного результата:** продуктовая ценность или качество не подтверждены.
- **Есть разовое использование, нет возврата:** задача может быть редкой, результат слабым или привычка не сформирована.
- **Есть повторное использование, нет оплаты:** проверить плательщика, цену, ограничения бесплатной версии и реальную ценность.
- **Есть оплаты и повторы:** усиливать канал и надёжность, продолжая следить за unit economics.

Не делай причинных выводов из сравнений с разной аудиторией без оговорок. Для маленьких выборок показывай абсолютные числа и описания кейсов.
