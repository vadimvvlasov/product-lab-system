# Release Checklist — [EXP-ID]

Gate G3 и Definition of Done экспериментальной функции. Копируется в PR или в эксперимент с `method: feature | launch`.

## Постановка
- [ ] Эксперимент прошёл G2: гипотеза, primary metric, scope и out-of-scope, риски, rollout/rollback заданы.
- [ ] Coding agent получил постановку по [[40-deliver]]: критерии приёмки и ограничения.

## Код и качество
- [ ] Основной сценарий реализован end-to-end.
- [ ] Diff, новые зависимости, секреты и миграции проверены человеком.
- [ ] Ошибки, таймауты и деградация зависимостей обработаны.
- [ ] Критерии приёмки покрыты тестами: unit, integration/API, e2e основного пути, negative/security cases по риску.
- [ ] Вручную на dev проверены пустые, ошибочные и пограничные состояния.
- [ ] Авторизация и изоляция данных правильного пользователя/тенанта проверены.
- [ ] Нет секретов и чувствительного пользовательского содержимого в логах/аналитике.
- [ ] Для AI/SQL-функций проверены ограничения, инъекции, таймауты и валидность результата.

## Измерение
- [ ] События видны в dashboard/logs на dev и совпадают с планом эксперимента.
- [ ] Source/campaign, `experiment_id` и variant сохраняются.
- [ ] Error и latency можно отличить от отказа пользователя.
- [ ] Guardrail-метрики доступны.
- [ ] Для критичных технических отказов есть alert/порог.
- [ ] Dashboard или запросы для review готовы.

## Rollout
- [ ] Smoke test на dev пройден.
- [ ] Production rollout выполнен по принятому процессу; при возможности — для ограниченной группы.
- [ ] Smoke test после deploy пройден, ошибки проверены.
- [ ] Rollback / feature flag проверен или понятен.
- [ ] Документация отражает фактическое состояние.
- [ ] Назначены дата/условие review и кто проверит результаты.

## Коммуникация
- [ ] Пост/объявление соответствует правилам площадки.
- [ ] Тестовый сценарий и ограничения объяснены.
- [ ] Пользователь знает, какие данные обрабатываются и куда они передаются.
