## Минимум для scoring

Для evidence-таблицы, которая используется в score и confidence, обязательны: `source_url`, `event_date`, `author_or_thread`, `verbatim_excerpt`, `signal`, `target_segment`, `source_quality`, `verified_by`. Для B/A также нужны `source_type` (минимум один `primary`), `author_id` и `verified_at`; `cluster` обязателен для дублей и перепечаток, `counter_evidence` — если найден. Для C пустой `verified_by` допустим: свидетельство просто не даёт B/A. Остальные поля — контекст: они нужны, когда применимы, но не блокируют строку. Полная схема сохраняется: поля не удаляются и не переименовываются.

## Поля

- `published_at` / `event_date` — дата публикации и, если отличается, дата самого события.
- `source_type` — `primary` (исходный материал автора о своём случае или данных: пост, отзыв, отчёт, документация; не перепечатка и не реклама продавца), `community` (обсуждение/тред, где автор и контекст видны, но исходный материал не выделен), `vendor` (страница продавца, реклама, affiliate), `SEO` (контент-ферма), `LLM` (сгенерированный текст).
- `author_or_thread` — если доступно и уместно.
- `author_id` — стабильный идентификатор автора (handle или URL профиля); один `author_id` = один голос. Если не определён — `unknown`.
- `verbatim_excerpt` — короткая точная выдержка; `paraphrase` — аккуратный пересказ, если цитата неуместна.
- `evidence_type` — допустимые значения и их смысл — в [[00-model]], § Тип свидетельства.
- `signal` — уровень L0–L5.
- `source_quality` — `ok | suspicious | affiliated` или короткое пояснение: свежесть, аффилированность, рекламный характер.
- `cluster` — один ID для кросспостов, перепечаток и почти идентичных фрагментов.
- `verified_by` — кто проверил URL, выдержку и дату. `human` — проверка человеком. `script` допустимо только для snapshot-проверки (см. § Snapshot-проверка): строка со статусом `PASS` в логе `pls_evidence verify`; `verified_at` берётся из лога. Сетевой verifier (`http_status`) не реализован, поэтому проверка по живому URL остаётся за человеком. `script` не повышает confidence: для B/A обязателен `human` (правила — [[20-screen]]). Пусто — не проверено.
- `verified_at` — дата проверки; без неё свидетельство не считается проверенным человеком и не даёт B/A.

## Snapshot-проверка

Для источников, которые автоматически не открыть (например, Reddit), владелец сохраняет клиппинг (Markdown с frontmatter `title`, `source`, `author`, `published`; допустимы окончания строк CRLF и BOM). Offline-проверка сверяет строки таблицы с клиппингами и пишет лог:

```
python -m pls_evidence verify --evidence <таблица.md> --clippings <каталог> --log <лог.json> [--strict] [--overwrite]
python -m pls_evidence report --clippings <каталог>   # сводка клиппингов с эвристическими флагами для приёма в inbox
```

Что проверяет `verify`: `verbatim_excerpt` буквально есть в клиппинге (в посте или в комментарии); `source_url` совпадает с `source` клиппинга; `published_at` и `author_id` совпадают с frontmatter (для выдержки из поста) или с заголовком комментария (для выдержки из комментария). Дата сравнивается по ISO-префиксу `YYYY-MM-DD` (метка времени в клиппинге или в строке не мешает). Автор в frontmatter может быть `[[wikilink]]`, простым или заключённым в кавычки значением, элементом списка; в строке допустимы префиксы `u/`, `/u/`, `@`, регистр не важен. Если у клиппинга нет автора или даты, поле получает `SKIP` и предупреждение в логе; `unknown` и пустая дата в строке тоже не проверяются. Статусы строки: `PASS`, `FAIL` (с указанием поля), `NO_SNAPSHOT` (клиппинга с таким URL нет; `FAIL`, если выдержка найдена в клиппинге с другим `source`). В лог пишутся `verified_at`, имя клиппинга, `content_hash` (sha256 файла), предупреждения по строке и список пропущенных файлов (`skipped_clippings`: файл без frontmatter, без `source` или нечитаемый; `report` показывает их строками с флагом `skipped`). Выдержка короче 20 символов после нормализации даёт предупреждение `excerpt shorter than 20 characters`, статус не меняется. Код выхода: 0 — нет `FAIL`; 1 — есть `FAIL`, а с `--strict` и `NO_SNAPSHOT`; 2 — ошибка входных данных или записи лога.

Нормализация перед сравнением выдержки (одинакова для выдержки и клиппинга): типографские кавычки и неразрывные пробелы становятся обычными; маркеры цитаты `>` в начале строки убираются; ссылки `[текст](url)` (в URL допустим один уровень скобок) заменяются текстом; экранирование Markdown (`\_`) снимается; маркеры `**` и `__` убираются; пробелы сжимаются. Регистр, пунктуация и порядок слов не меняются. Знак `|` внутри ячейки пишется `\|`.

Чего `verify` не делает: не подтверждает claim, не доказывает подлинность клиппинга (клиппинг мог быть изменён), не пишет `verified_by` в таблицу и не заменяет человека для B/A. Человеку остаётся сверить подлинность клиппинга и смысл свидетельства, а не перепечатывать цитату.

## Правила

- На каждый факт — первоисточник. Не записывать вывод модели без URL и выдержки, которая его поддерживает.
- Отмечать дату события, если она отличается от даты публикации; старые сообщения могут описывать уже решённую проблему.
- Кросспосты, перепечатки и дубли связывать одним `cluster`; число упоминаний ≠ число независимых пользователей.
- Один `author_id` — один голос, даже если у автора несколько постов в разные даты. Новый автор с новым случаем — отдельный голос.
- `source_type: vendor | SEO | LLM` и `source_quality: suspicious | affiliated` не считаются независимым L2 и не повышают confidence.
- Для B/A ключевые свидетельства проверяются человеком: `verified_by: human` и `verified_at`; без проверки — максимум C. A требует проверенный primary-источник, подтверждающий именно заявленное утверждение (проблема / использование / оплата).
- Неразрешённый `counter_evidence` — потолок на шаг ниже: A → B, B → C, C остаётся C. Снижение из A в B фиксируется как `B (снижено из A)`: контраргумент остаётся записанным, но не требует повторно выполнить условие «контраргумента нет».
- Строки из разговоров: `source_type: primary`, `source_url` — ссылка на заметку лида, `author_id` — публичный handle; `verified_by: human` и `verified_at` — только если владелец сам провёл разговор и записал дословную выдержку; гипотетические ответы («купили бы») — `signal: L1`. Протокол — [[customer-conversation]].
- «Интересно», лайки и голоса в опросе не равны готовности платить.
- Сохранять контраргументы и случаи, когда пользователи решают задачу бесплатно или редко.
- Спорное значение — `unknown`, а не придуманное число.
- Коротко цитировать; не копировать большие части чужих текстов. Соблюдать правила площадки, авторские права и ограничения доступа.
